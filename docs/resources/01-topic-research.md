## 3 选题现状:moonpatch 的生态位

### 3.1 问题定义

AI 编程 Agent 的核心工作循环是"生成补丁 → 应用到代码库"。但 LLM 生成的 unified diff 经常出现上下文漂移(行号偏移、空白差异、编码差异),现有工具容错能力有限,导致 Agent 补丁应用失败率高、需要多轮重试。一个**高容错、可测试、可组合** 的 patch 引擎,是 AI 原生开发工具链的底层基础设施。

"这不是提示词比赛。我们更关注工程边界、测试质量、开源合规和可维护性。AI 可以参与开发,但最终成果必须由参赛者理解并负责。" —— 2026 MoonBit 黑客松官方定位

### 3.2 竞品与现状分析

现有方案| 容错能力| 形态| 与 MoonBit 生态关系  
---|---|---|---  
GNU patch| 基础偏移容错(fuzz)| 系统命令行工具| 无关  
git apply| 有限模糊匹配(-C 参数)| Git 子命令| 无关  
aider search-replace| 专有格式,非标准 unified diff| Python 库| 无关  
SeekMoon 内置 diff| 已集成 token/AST 级 diff,能力未独立成库| 官方 AI IDE 内部模块| 内部能力,生态无法复用  
mooncakes.io 生态| 检索确认:无公开的 diff/patch 处理包| **空白**  
  
生态位判断

"MoonBit 生态内空白 + AI Agent 时代通用刚需"双重定位成立。与 GNU patch/git 的差异点不在"更容错"一点,而在于**以库形态提供、可被 MoonBit 生态内的 Agent 工具直接组合** ——这是系统工具做不到的。

## 4 实施方案:如果要做,怎么做

### 4.1 MVP 范围与四周里程碑

周次| 交付物| 验收判据  
---|---|---  
W1| Myers diff 算法 + unified diff 生成| 50+ 单测;对拍 100 组随机字符串对  
W2| unified diff 解析 + 精确 apply(路径解析、模式位)| 往返测试:diff→apply 后与目标全等  
W3| 模糊 apply:上下文偏移匹配、空白归一化、hunk 降级重试| 构造漂移场景用例集,成功率与失败原因可报告  
W4| 对抗性测试集 + 与 GNU patch/git apply 行为基准对比 + 文档与 README 演示| moon test 全绿;README 可复现演示  
  
### 4.2 技术路线

零三方依赖(仅 moonbitlang/core) Myers O(ND) 算法 hunk 级降级重试 native 优先、wasm-gc 验证 moon test 全程测试驱动

依赖就绪度评估:核心依赖仅标准库,三档分级中属"可绕过"级——无外部阻塞依赖,这是五个候选中依赖风险最低的一个。

### 4.3 赛事验收标准逐条映射

赛事验收标准| moonpatch 对应  
---|---  
MoonBit 为主实现语言| 100% MoonBit,零 FFI  
仓库公开、提交可追踪| 公开仓库,按周提交,Issues 记录决策  
能运行(README/示例/测试)| CLI 工具 + moon test 全绿 + README 演示  
实质新增工作| 全新项目,无存量代码  
开源合规| Apache-2.0;算法为公共知识(Myers 1986 论文),无移植许可问题  
AI 可解释| AI 辅助开发全程留痕;所有技术选型(算法/数据结构/容错策略)可口头答辩说明  
  
### 4.4 需求风险登记册

编号| 风险描述| 概率| 影响| 等级| 应对措施  
---|---|---|---|---|---  
RK-01| 模糊 apply 组合场景爆炸,测试矩阵失控| 3| 3| 9 中| 固定随机种子生成用例 + 分层测试(精确/偏移/空白/混合)  
RK-02| 与 GNU patch 行为不一致导致"正确性"争议| 2| 4| 8 中| 以 git apply 语义为对齐基准;差异行为显式写入文档  
RK-03| Wasm 后端字符串性能不达标| 2| 3| 6 低| native 为基准主后端,wasm-gc 做兼容验证;基准数据留痕  
RK-04| 单人参赛时间不足| 2| 4| 8 中| MoSCoW 裁剪:模糊 apply 三层策略按优先级砍,精确 apply 为 Must 不可砍  
  
### 4.5 组队与排期建议

单人可完成核心闭环(Must 项);若组 2 人队,建议"算法实现 + 测试与文档"分工,奖金人均 1/2。不建议 3 人队——MVP 工作量不足以三人并行满载。

## 5 价值评估:做了是否有价值

赛事价值确定性回报 + 奖金上行

月度支持 500 元(150 启动 + 350 完成)为完成即得的基本盘;季度奖金池 8 万元(一等奖 12,000 × 1–2 名);"AI 原生工具链"叙事与赛事主题、官方对 SeekMoon 方向的投入高度同频,答辩辨识度高。

生态价值填补空白的基础设施

mooncakes.io 无 diff/patch 包,补齐后即为生态唯一实现;MoonBit 官方主推"AI 原生工具链",Agent 基础件属于其战略方向;后续可演进为语义 diff(基于 moonbitlang/parser)与 Agent SDK 组件。

个人价值可积累的长期资产

开源署名作品(算法库生命周期长于业务项目);季度决赛晋级者获 MoonBit MVP 计划免笔试资格(补贴 2k–5k/月、可远程);官方明确获奖项目有实习直通车机会。

机会成本提示

若首要目标是"拿奖概率最大化"而非"叙事与长期价值",moon-png(PNG 编解码,可交付确定性五星、测试素材官方现成)是更稳的选择;moonpatch 的相对优势在答辩叙事与生态战略契合,劣势是容错算法的"正确性边界"需要更严格的测试论证。

价值结论:值得做

赛事、生态、个人三重价值均成立;风险集中在工程执行层(可测试化),已配置应对措施;不涉及资金、合规敏感面。
